# 이모지 타일 로스터 97종 + 노름꾼 카드 효과 — 설계안 (2026-07-29)

이모지 타일(engine id: `joker`) 풀을 36 → **97종**으로 전면 재설계하고, 타일별 해금
조건과 노름꾼 카드 14장의 효과를 확정한다.

**이 문서는 검토용이다.** 각 행 앞의 `[ ]`가 채택 체크박스다. 체크된 것만 GDD §11에
편입하고 구현한다. 미채택 행은 이 문서에 보류로 남긴다.

> **문서 언어.** 검토 편의를 위해 본문은 한국어, 이름은 `nameKo / nameEn` 병기(코드베이스
> 관행). GDD 편입 시 §11 표는 기존대로 영어 우선 + `nameKo`.

## 1. 설계 원칙

### 1.1 이 게임 고유의 아이디어 광맥

발라트로 조커를 번역하는 것이 아니라, 이 게임에만 있는 훅에서 뽑는다. 각 축이 최소
3장 이상을 담당하게 배분했다.

| 축 | 근거 | 비고 |
|---|---|---|
| 문자 속성 (모음/자음 · 알파벳 순서 · 희귀문자) | GDD §2.1 | 발라트로의 랭크/수트 자리 |
| 재료 9종 | §2.2 | 도자기·광택·유리·석재·연판·상아·황동·목재 |
| 폰트 5종 (= 씰) | §2.3 | goldPlay / chipPlay / discardGain / retriggerPlay |
| 등록어 4종 | §3.1 | Standard·Formal·Slang·Vulgar |
| 품사 9종 | §4.2 | 문장 패턴의 뼈대 |
| 문장 패턴 12종 + 레벨 | §5.2·§5.4 | 발라트로 족보 자리 |
| **글자 족보 6종** | §5.5 | §5.5가 "이모지 미개척"이라 명시한 공백 — 이번에 개척 |
| 횡설수설 (gibberish) | §6.4 | 하이카드 빌드 |
| 페이즈 / 버리기 / 주머니 고갈 | §6.3·§6.6 | 속공 ↔ 서사 대립축 |
| 유니슨 | §5.3 | 플러시 자리 |
| 사전 속성 (길이·첫끝글자·회문·연속) | §3.2 | 이 게임만 가능한 축 |
| 상점 경제 / 소모품 / 바우처 / 판본 | §9·§11.8 | 골드·패시브 축 |
| 보스 12종 | §8.3 | 대(對)보스 특화 |

### 1.2 축별 겹침 밀도 (파워 커브의 뼈대)

발라트로 분석에서 가져온 원칙 그대로 적용한다.

- **스노우볼 축 — 성장형 × 곱배수:** Rare·Legendary에 몰아넣는다. Common에는 성장형이
  있어도 곱배수와 겹치지 않는다 (예: `견습생`은 성장이지만 합배수).
- **리스크-리워드 축 — 확률 × 골드 / 카드파괴:** Uncommon 중심. 체감형도 여기 붙는다.
- **초반 안정 축 — 순수 합배수 / 칩:** Common 중심, 겹침 최소. 이해 비용이 0이어야 한다.
- **규칙 파괴 축 — 패시브:** Legendary 전용에 가깝게. Rare 패시브는 "규칙을 넓히는" 정도까지.

### 1.3 발동 순서 — 3계층 (신규 규칙, GDD §11 개정 대상)

기존 GDD §11은 "선반 순서 = 발동 순서(좌→우, 드래그 재정렬)" 하나뿐이었다. 그 위에
**배치와 무관한 고정 3계층**을 얹는다.

1. **핸드를 플레이해 득점할 때마다** 발동하는 이모지
2. **핸드에 남은 타일마다** 발동하는 이모지
3. 그 외 (무조건 발동 · 문장 패턴 관련 · 판본 강화)

같은 계층 안에서만 선반의 좌→우 순서가 적용된다. 따라서 합배수를 왼쪽, 곱배수를
오른쪽에 두는 전략은 **계층 내부에서만** 유효하다. 칩은 곱연산이 없으므로 순서 무관.

문장 패턴 포함 판정은 **최종 족보나 득점과 무관하게 그 패턴이 포함되기만 하면** 발동한다.

### 1.4 표 읽는 법

- **L** = 레이어. 1 = 문자/타일 · 2 = 등록어(suit) · 3 = 문장/페이즈
- **특성** = 합 / 곱 / 칩 / 골드 / 리트 / 성장 / 체감 / 확률 / 생성 / 파괴 / 패시브
- **해금** = `시작` 은 처음부터 사용 가능. 나머지는 조건 (§8)
- 모든 수치는 `balance.ts`로 갈 **플레이스홀더**다 (GDD §11 서두 규칙과 동일)

## 7. 지수 효과 4장 — 성장 3 + 연속 1

### 7.1 왜 따로 다루나

일반 성장형은 `+0.1 ×Mult`씩 **선형**으로 붙는다 (R5·R6·R16·R24).
여기 묶인 효과는 `×1.5ⁿ`처럼 곱해지지만, R14 각운 사슬은 블라인드 종료 시
사라지는 연속 보너스이므로 성장형이 아니다. 나머지 3장만 성장형으로 분류한다.

### 7.2 4장의 배수식과 현실적 n

| 이모지 | 배수식 | n의 자원 | 8앤티 현실 n | 8앤티 배수 | 무한모드 위험 |
|---|---|---|---|---|---|
| R13 활자 주조소 | ×1.5ⁿ | 영구 파괴된 타일 수 | 3–10 | ×3.4 – ×57 | 중 (주머니 고갈이 자연 제동) |
| R14 각운 사슬 | ×1.5ⁿ | 연속 각운 페이즈 수, **블라인드마다 초기화** | 2–5 | ×2.3 – ×7.6 | 낮음 |
| X4 무한 서사 | ×1.25ⁿ | 사용 페이즈 수, **블라인드마다 초기화** | 6–12 | ×3.8 – ×14.6 | **높음** |
| X5 여백의 서 | ×2ⁿ | 비어 있는 슬롯 수 | 0–3 | ×1 – ×8 | 중 |

각 n이 서로 다른 자원(파괴 / 각운 / 페이즈 / 슬롯)에 묶여 있어 한 빌드가 넷을 동시에
키울 수 없다. 이것이 4장 제한의 실질적 근거다.

### 7.3 확인해야 할 상한 (`src/sim` 과제)

1. **X4 × R5(서사 시인) × R6(수집가).** GDD §11.7이 이미 "아무도 일찍 끝내지 않는 문제"로
   지목한 스택에 지수가 들어간다. 제동은 두 개뿐 — 목표 증가 절반, 주머니 고갈(§6.6).
   **최우선 시뮬레이션 대상.**
2. **X5 × 노름꾼 우중인.** 우중인이 화이트 판본을 주면 슬롯이 +1 되고, 그 칸은
   비어 있다 → X5의 n이 공짜로 오른다. 우중인을 여러 장 먹으면 n이 무제한으로 늘어난다.
   **완화안: X5의 n에 상한 3을 명시** (`min(빈 슬롯, 3)` → 최대 ×8). 채택 여부 결정 필요.
3. **X5 × 노름꾼 사케 잔.** 사케 잔이 나머지 이모지를 전부 파괴하면 X5만 남고 슬롯이
   전부 빈다. 2번의 상한이 이 경로도 함께 막는다.
4. **R13 × 유리 빌드 × 노름꾼 나비/보름달.** 파괴가 곧 성장이므로 나비($20 + 5장 파괴)는
   R13에게 순수 이득이 된다. 노름꾼의 "양날" 정체성이 이 조합에서 무력화된다 — 의도된
   시너지로 남길지, R13의 성장 조건에서 노름꾼 파괴를 제외할지 결정 필요.

## 8. 해금 시스템

### 8.1 규칙

1. **시작 개방 타일**과 **해금 타일**이 있다. 위 표의 `해금` 열이 `시작`이면 전자.
2. **미해금 타일은 등장하지 않는다.** 상점 이모지 슬롯, 부적 팩, 노름꾼 학과 해(무작위
   레어) — **모든 롤 풀에서 제외**한다. **예외: 레전더리(§6)는 해금 게이트가 없으므로
   노름꾼 봉황은 항상 5장 전체를 후보로 쓴다.**
3. **시드 없는 런에서만 진행도가 적립된다.** 시드를 입력한 런(`NewRun.tsx`의 `seeded`)은
   진행도를 전혀 쌓지 않는다. GDD §9.4 바우처 업그레이드가 이미 쓰는 규칙과 동일.
4. **진행도는 프로필 스코프**다. 런이 끝나도, 런을 포기해도 유지된다.
5. **Collection 노출.** 미해금 타일은 §9.4 바우처와 같은 포맷으로 **발견되지 않음 /
   Undiscovered**로 표시하고, 이름·효과·해금 조건·진행도를 전부 숨긴다. 시드 없는 런에서
   플레이하라는 힌트만 보여준다.
6. **Settings의 "전부 해금" 오버라이드**는 §13 색 해금과 동일하게 **표시만** 풀고 실제
   발견으로 치지 않는다.

### 8.3 저장 (구현 메모)

- 새 키 **2개**: `wj.emojiUnlocks` (해금된 id 집합) · `wj.emojiProgress` (카운터 맵).
- 둘 다 **플레이어 진행도**이므로 `src/ui/storage.ts`의 `SAVE_KEYS`에 넣고, 데스크톱에서는
  `%APPDATA%/Play the World/saves/profile.json`으로 간다.
- `desktop/save-store.js`의 `SAVE_KEYS` **중복 목록도 같이 갱신**해야 한다 (`desktop/`은
  `src/`를 import할 수 없어 복제되어 있고, 어긋나면 테스트가 실패한다).
- `wj.unlocks`(색 해금)와 **합치지 않는다.** 다른 시스템이고 다른 판정 규칙을 쓴다.
- 진행도 적립은 **UI 레이어**에서 한다. 엔진은 계속 헤드리스여야 하므로 `RunState`에
  해금 정보를 넣지 않는다 (§CLAUDE.md의 프로필 플래그 규칙과 동일).

### 9.3 확정한 2장의 근거

14장은 발라트로 스펙트럴의 사실상 1:1 포팅이다 (멧돼지=Ankh · 휘장=Cryptid ·
나비=Immolate · 학과 해=Wraith · 보름달=Familiar · 다리=Ouija · 사슴=Black Hole ·
봉황=Soul · 폰트 4종=Deja Vu/Talisman/Trance/Medium 자리). 빠진 스펙트럴 중 **조커를
직접 건드리는 두 장**이 정확히 미정 2장 자리에 남아 있었다:

- **Ectoplasm** → 우중인. 화이트 부여 + 핸드 크기 영구 -1.
- **Hex** → 사케 잔. 레인보우 부여 + 나머지 전부 파괴.

"이모지 타일 기획이 확정된 이후에 정한다"는 지시와 정확히 맞아떨어진다 — 둘 다 이모지
타일을 대상으로 하는 카드이기 때문이다. 판본 시스템(§11.8)이 이미 구현되어 있어
추가 시스템 없이 붙는다.

### 9.4 폰트 4장이 밋밋한 문제 (검토 필요)

제비·기러기·휘파람새·뻐꾸기는 **같은 카드의 폰트만 다른 4장**이고, 전부 순수 상방이다.
"희귀하고 강력하고 대체로 양날"이라는 §10.3의 정체성과 어긋난다. 세 가지 안:

- **안 A (현행 유지).** 화투 세트의 시각적 통일성을 위해 그대로 둔다. 대신 잉크 팩 안에서
  **여러 장 동시 등장을 막는다**.
- **안 B (대가 부여).** 각 카드가 폰트를 부여하면서 **핸드의 다른 무작위 타일 1장을 파괴**
  하게 한다. 양날 정체성 회복, 4장 모두 동일 대가.
- **안 C (통합 후 자리 재활용).** 4장을 "선택한 폰트를 부여" 1장으로 합치고, 남는 3자리에
  새 노름꾼을 기획한다. 화투 아트 4장 중 3장이 놀게 되므로 아트 낭비.

**추천: 안 B.** 아트를 전부 쓰면서 정체성이 맞고, 위 R13(활자 주조소)·U30(파쇄기) 같은
파괴 축 빌드에 새 연결점이 생긴다.

## 10. 밸런스 압력점 (playtest / sim 우선순위)

1. **X4 무한 서사 × R5 × R6** — §7.3-1. 지수 × 선형 × 선형 스택. 최우선.
2. **X5 여백의 서 × 우중인 / 사케 잔** — §7.3-2·3. 빈 슬롯 n의 상한 결정이 선행돼야 한다.
3. **R13 활자 주조소 × 나비** — §7.3-4. 노름꾼의 대가가 이득으로 뒤집힌다.
4. **R12 일필휘지 × R8 사채업자** — GDD §11.7이 이미 지목한 속공 경제 콤보. R12를 Rare로
   강등했으므로 **등장 빈도가 오른다** (5% 풀). 재검증 필요.
5. **U34 거북 방석의 핸드 크기 +4** — 핸드 11 → 15. GDD §6.2가 핸드 크기를 밸런스 노브로
   명시했으므로 +4는 과할 수 있다. +3부터 시뮬레이션.
6. **R17 우화 수집 (소모품 1개당 ×1.2)** — 소모품 슬롯을 늘리는 바우처와 곱해진다.
   슬롯 5개면 ×2.49. 슬롯 상한 확인 필요.
7. **C18 희귀 문자 애호 (+40 Chips)** — 주머니 재조정(§2.1, 98→68)으로 희귀 문자가 **~2배**
   자주 나온다. 발라트로 값을 그대로 쓰면 안 되는 대표 사례.
