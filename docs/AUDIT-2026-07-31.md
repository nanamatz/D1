## 1. 통일성

### 1.1 툴팁 — 용어 · 문장구조 · 강조

**✅ 이미 잘 된 것**

- 강조 마크업 `[m:] [c:] [b:] [n:] [k:] [a:] [g:] [$:] [p:]`은 `richtext.tsx`가
  단일 파서로 처리하고, **en/ko 전체 설명군에서 태그 종류·개수 불일치 0건**.
  (`jokerdesc·consumabledesc·voucherdesc·bossdesc·patterndesc·materialdesc` 전수 비교)
- 툴팁 본문 생성은 `descriptions.ts`가 유일 경로 (`jokerTooltipBody`,
  `consumableTooltipBody`, `consumableTooltipExtra`, `consumableAxisTip`,
  `fontDescKey`). 컴포넌트가 문자열을 직접 조립하는 곳 없음.
- 패널 클리핑 방지: `Tooltip.tsx:147`이 `document.body`로 portal.

**❌ U-1 · 문장 종결 부호가 그룹마다 다르고, 같은 그룹 안에서도 갈린다** (중)

| 그룹 | en | ko |
|---|---|---|
| `jokerdesc` (116) | 마침표 0 | 마침표 0 |
| `voucherdesc` (32) | 마침표 0 | 마침표 0 |
| `bossdesc` (16) | 마침표 **0** | 마침표 **16** |
| `consumabledesc` (43) | 마침표 30 / 없음 13 | 마침표 30 / 없음 13 |

- ko의 `bossdesc`만 전부 `~합니다.` 종결이고 `jokerdesc`는 전부 명사형 단편이다.
  같은 툴팁 UI에서 두 문체가 번갈아 나온다.
- `consumabledesc`의 무마침표 13개 = Constellation 12 + `magnifier`.
  Constellation 12개는 `consumableTooltipBody()`가 `pack.constellationLevels`로
  덮어쓰므로 **화면에 뜨지 않는 죽은 문자열**이다(→ U-2). 실제 불일치는
  `consumabledesc.magnifier`("Reveals up to 3 …", 마침표 없음) 대
  `consumabledesc.fable1`("Show up to 3 …", 마침표 있음) — 사실상 같은 효과인데
  문구도 종결도 다르다.
- **처리:** 종결 규칙을 그룹이 아니라 **문서 전체**로 하나 정한다(권장: 전부
  마침표 없음 — 116개 `jokerdesc`가 이미 그렇다). ko `bossdesc` 16행에서
  마침표를 걷어내고 문체를 명사형으로 맞춘다. `magnifier`/`fable1`은 한쪽으로 통일.

**❌ U-2 · 화면에 절대 뜨지 않는 Constellation 설명 12행 × 2언어** (하)

`descriptions.ts:41-46`이 `CONSTELLATION_PATTERN[id]`가 있으면 무조건
`pack.constellationLevels`를 반환한다. `consumabledesc.aries…scorpio` 24행은
도달 불가. R-01과 같은 성격의 잔재.

**❌ U-3 · 수치 강조 규칙이 불완전하다** (중)

`richtext.tsx`는 `[n:]`을 "pack 문구의 개수"로만 한정한다. 그 결과 en 기준
**174행**, ko 기준 **187행**의 설명에 태그 없는 맨 숫자가 남는다.

```
jokerdesc.longWordFan   :: [c:+30 Chips] if the word is 5 letters or longer
jokerdesc.shortAndSharp :: [m:+8 Mult] if the word is 3 letters or shorter
bossdesc.historyBook    :: −2 phases in this boss blind      ← 전부 무강조
bossdesc.bond           :: [$:−$1] per phase played          ← 같은 boss군인데 강조 있음
consumabledesc.fable4   :: Enhance 2 selected tiles into Lead Plate tiles.
```

같은 `bossdesc` 안에서 `bond`는 강조, `historyBook`·`budgetBook`은 무강조다.
플레이어 기준 "−2 phases"와 "−$1"은 동급 정보다.
**처리:** `[n:]`의 의미를 "pack 개수"에서 "게임 규칙 수치"로 확장하고
조건 수치(5글자, 3글자, 2장, −2 페이즈)에 일괄 적용. 파서 변경 불필요 — locale만 수정.

**❌ U-4 · 번역 누락 1건 (플레이어 노출)** (중)

### 1.3 기능적 균형

**❌ U-6 · Rare 등급의 개별 접근성이 사실상 붕괴** (상 — 밸런스)

- 오퍼 가중치: Common 70 / Uncommon 25 / Rare 5 (`balance.ts:252-254`)
- 실제 풀 크기: Common **24** / Uncommon **42** / Rare **45**
- `offers.ts:42` `sampleJokerDefs`는 Balatro식 2단계(등급을 가중 추첨 → 등급 내 균등)다.
  등급 확률은 풀 크기와 무관하지만, **개별 타일 확률은 풀 크기에 반비례**한다.

| 등급 | 풀 | 개별 타일 상대 확률 |
|---|---:|---:|
| Common | 24 | 70/24 = **2.92** |
| Uncommon | 42 | 25/42 = **0.60** |
| Rare | 45 | 5/45 = **0.11** |

특정 Rare 하나가 특정 Common 하나보다 **약 26배** 덜 나온다. 저작된 116종 중
Rare가 39%(45종)인데 오퍼 슬롯의 5%만 배정된다 — 콘텐츠 대부분이 8챕터 런에서
사실상 안 보인다. Balatro는 Rare 풀이 *작기* 때문에 같은 가중치가 성립했다.
**처리(택1):** ① 가중치를 풀 비율에 맞춰 재조정(예: 55/30/15) ② Rare 45종 중
일부를 Uncommon으로 강등 ③ 등급별 균등이 아니라 전체 균등 + 등급 가중을
곱하는 방식으로 샘플러 변경. ①이 최소 변경.

**❌ U-7 · Legendary 5종은 획득 경로가 사실상 없다** (중 — 밸런스)

따라서 4× 설정에서도 화면 전환, 팩 개봉, Cash Out 라인 공개(`useReveal` 380ms),
FLIP 손패 정렬(`hooks.ts:112,128` 340ms/280ms), 보스 인트로, 모든 CSS
`@keyframes`는 **1× 그대로** 돈다. "게임 속도"라는 이름이 지키는 범위와
플레이어가 기대하는 범위가 크게 다르다.
**처리:** U-10의 duration 토큰을 만들고 `--speed` 배율을 `<html>`에 써서
`calc(var(--dur-base) / var(--speed))`로 잇는다. 토큰화가 선행 조건.

## 2. 무결성

### 2.1 데이터 손실

**✅ 손실 위험은 낮다.** 근거:

- `storage.ts`가 유일 경로이고 8개 `SAVE_KEYS`를 3슬롯 봉투로 다중화한다.
  레거시 flat 값은 P1로 자동 해석되고, P1 단독일 때는 flat 형식을 **유지**해서
  불필요한 재작성이 없다(`writeProfileRaw:152`).
- 모든 read/write가 try/catch로 감싸져 있고 어떤 경로도 throw하지 않는다.
- `run.json` / `profile.json` 분리로 `persist.ts`의 `VERSION` 불일치 폐기가
  컬렉션·통계를 같이 날리지 않는다.
- desktop 이관(`migrate:74`)이 `fresh` 플래그로만 동작하고, 복사 후 원본을
  삭제해 "세이브 폴더 지우기"가 되살아나지 않게 막았다.
- `desktop/save-store.js`의 `SAVE_KEYS` 사본 드리프트는 테스트가 감시 중.
- `loadRun()`이 미지의 joker/consumable id를 필터링 — 카드 은퇴가 세이브 폐기를
  유발하지 않는다.

**⚠️ I-1 · 프로필 슬롯 삭제가 부분 실패할 수 있다** (하)

1. **Voucher/Pack 아트 PNG가 1024×1024, 개당 1.6~1.9 MB.** 런타임 렌더 크기는

2. **Gambler 아트가 SVG인데 개당 674 KB** (`Geese`, `Cuckoo`, `BarnSwallow`…).

   픽셀아트를 벡터로 들고 있는 것 자체가 잘못된 포맷 선택. PNG 전환 시 **~20 MB 절감**.
3. **폰트 9.2 MB / 554 파일.** `main.tsx:7-17`이 11개 weight CSS를 import하고,
   @fontsource는 각 weight마다 모든 unicode subset(latin·latin-ext·cyrillic·
   greek·vietnamese + Noto Sans KR의 korean 100여 조각)을 `.woff`와 `.woff2`
   양쪽으로 배포한다. **런타임은 `.woff2`만 가져가므로 `.woff` 5.2 MB는 순수 사장**.
   subset 지정 import(`…/korean-500.css`) + woff 제외로 **~7 MB 절감**.
4. **JS 단일 청크 2.2 MB.** `lexicon.browser.ts`가 `data/lexicon.json`(1.6 MB)과
   `dictionary.txt`(258 KB)를 빌드 타임 인라인한다 — 오프라인 규약상 `fetch`는
   금지이므로 **인라인 자체는 유지해야 한다**. 다만 이 30,262행 테이블은
   `{suit, pos[]}` 반복 문자열이라 압축 표현(suit 1글자 + POS 비트마스크)으로
