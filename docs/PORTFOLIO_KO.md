### 한 줄 소개

**Play the Wor!d**는 포커 핸드 대신 **영어 단어와 문장 구조**로 점수를 만드는 로그라이트다. 플레이어는 제한된 알파벳 타일로 매 페이즈 단어를 만들고, 여러 단어의 품사를 이어 문장 패턴을 완성하며, Emoji Tile과 타일 강화를 조합해 자신만의 빌드를 만든다.

게임은 무채색·무음의 세계에서 시작한다. `YELLOW`, `RED`, `MUSIC` 같은 단어를 실제로 플레이하면 색과 소리가 영구적으로 해금된다. 제목의 "세계를 플레이한다"를 규칙과 연출로 직접 경험하게 만든 것이 이 프로젝트의 정체성이다.

> **핵심 키워드:** 단어 조합 · 문장 빌딩 · 덱빌딩 로그라이트 · 데이터 주도 설계 · 결정론적 시뮬레이션 · 픽셀 아트/CRT

### 기획 배경

기존 단어 게임은 대개 한 번 만든 단어의 길이나 희귀 글자를 평가하고 곧바로 다음 문제로 넘어간다. 순간 퍼즐의 재미는 강하지만, 이전 선택이 다음 선택에 영향을 주는 장기 전략과 빌드 다양성을 만들기 어렵다. 이 프로젝트는 한 가지 질문에서 출발했다.

> "단어 하나를 잘 만드는 재미를, 한 판 전체의 전략으로 확장할 수 있을까?"

그래서 점수를 세 개의 시간축으로 나눴다.

1. **글자 단위** — 어떤 알파벳과 강화 타일을 쓸 것인가
2. **단어 단위** — 길이·어휘 격식·반복 구조로 어떤 단어 점수를 만들 것인가
3. **문장 단위** — 지금 만든 단어를 다음 페이즈 단어와 어떻게 연결할 것인가

덕분에 플레이어는 매 순간 "지금 가장 비싼 단어"와 "마지막에 더 강한 문장을 만드는 단어" 사이에서 선택하게 된다.

### 핵심 플레이 흐름

`Starting Pouch·Record 선택 → Draft → Revision → Deadline → Fee Settlement → Stationery Shop → 다음 Chapter`

- 한 라운드는 기본 5페이즈, 버리기 4회.
- 각 페이즈에서 핸드 10장 중 일부를 골라 단어 하나를 제출한다.
- 단어 점수는 즉시 누적되고, 품사는 Sentence Tray에 차례로 쌓인다.
- 라운드가 끝나면 전체 품사 배열이 12종 문장 패턴 중 하나와 일치하는지 판정한다.
- 목표 점수를 넘기면 정산 후 문방구에서 타일·이모지 타일·소모품·바우처로 빌드를 강화한다.
- Draft와 Revision은 공개된 Editorial Perk를 받고 스킵할 수 있지만, Deadline 보스전은 반드시 플레이한다.
- Chapter 8의 Deadline을 통과하면 기본 승리, 이후 Endless Mode로 이어진다.

### 게임을 차별화한 네 가지 시스템

**① Word Hands — 단어를 '족보'로 해석**
사전 유효성만 보지 않고 글자 배열 자체를 족보로 평가한다. `BOOK`의 연속 글자는 Twin, 6글자 이상은 Longword, `LEVEL`은 Palindrome, 다섯 모음을 모두 담으면 Vowel Flush, 연속 알파벳 5개는 Straight. 여기에 Type Economy·Vowelless·Grand Palindrome을 더해 **총 9종**. 여러 조건을 만족해도 가장 높은 족보 하나만 적용되며, 희귀 족보는 최초 달성 전까지 이름을 숨겨 발견의 재미를 남긴다.

**② Register Suit — 어휘의 '말투'를 수트로**
유효 단어는 Standard / Formal / Slang / Vulgar 중 하나의 격식으로 분류된다. 일반 카드 수트와 달리 출현 빈도와 보상이 비대칭이라, 희귀한 어휘를 기억하고 쓰는 행위 자체가 전략이 된다. 같은 격식을 이어 붙이면 **Unison** 보너스가 붙어, "이번 문장을 어떤 어조로 통일할 것인가"가 빌드의 한 축이 된다.

**③ 유한한 문법 퍼즐 — 자유 문장 대신 품사 배열**
자유 문장의 의미 판정은 불확실한 자연어 처리나 네트워크 모델을 요구한다. 그 범위를 의도적으로 줄여, 각 단어의 품사 후보를 조합한 뒤 전체 배열을 **12종 Sentence Pattern**과 비교한다. `CAT EATS FISH`는 `명사 + 동사 + 명사`의 Transitive로 판정되고, 관사·형용사·부사는 뼈대를 깨지 않는 수식어로 흡수되어 추가 점수를 준다. `TASTE`처럼 다중 품사 단어는 가능한 배치를 모두 탐색한 뒤 최고 패턴을 고른다. 결과적으로 오프라인에서 항상 같은 판정, 테스트 가능한 규칙, 설명 가능한 UI를 동시에 얻었다.

**④ Chromatic Unlocks — 단어가 세계를 복원한다**
첫 실행은 무채색이고 음악·효과음도 잠겨 있다. 게임 안에서 `YELLOW`를 만들면 노란 계열이 돌아오고, `MUSIC`을 만들면 음악이 열린다. 단순 업적 목록이 아니라 제목과 규칙을 잇는 장치이자, 첫 단어 제작 튜토리얼이자, 프로필별 장기 수집 목표다. 동시에 "색에만 정보를 의존하지 않는 UI"를 강제하는 설계 제약으로도 작동한다.

## 2. 개발 중점 사항

아이디어의 규모보다 **플레이어가 이해할 수 있는 규칙 / 콘텐츠가 늘어나도 버티는 구조 / 플랫폼이 달라져도 재사용되는 엔진**에 중점을 뒀다.

### 2.1 헤드리스 엔진 — 규칙과 화면의 분리

게임 규칙은 `src/engine/`에 격리되어 DOM·React·브라우저 API에 의존하지 않는다. UI는 엔진 결과를 소비하지만 엔진은 UI를 모른다. 같은 엔진을 브라우저·Electron·자동 플레이 시뮬레이터가 그대로 재사용하며, 이후 모바일 패키징에서도 규칙을 다시 쓰지 않아도 된다.

| 레이어 | 책임 | 원칙 |
|---|---|---|
| `src/engine` | 점수, 핸드, 문방구, 보스, 경제, 진행 | 순수 TypeScript · 브라우저 의존 금지 |
| `src/ui` | React 화면, 입력, 애니메이션, 오디오, 접근성 | 엔진 결과를 표현할 뿐 규칙을 재구현하지 않음 |
| `src/sim` | 자동 플레이와 밸런스 검증 | UI 없이 수천 회 런 실행 |
| `data` | 사전과 품사·격식 데이터 | 런타임 네트워크 요청 없이 번들에 포함 |
| `desktop` | Electron 셸과 파일 저장 | 빌드 결과만 로드, 의존 방향 역전 금지 |

### 2.2 데이터 + 이벤트 훅 — 분기 폭발 방지

150개 Emoji Tile 효과를 점수 파이프라인의 조건문으로 넣으면 콘텐츠가 늘수록 핵심 로직이 무너진다. 그래서 Emoji Tile을 **데이터 + 이벤트 훅**으로 정의했다. `blindStart`, `wordScoring`, `tileScoring`, `sentenceScoring`, `blindEnd`, `shopEnter` 같은 이벤트에 각 타일이 필요한 훅만 등록한다. 새 효과가 필요하면 특정 타일을 하드코딩하는 대신 **공통 이벤트 계약을 확장**한다. 보스·바우처·스킵 보상·Gambler 카드도 같은 원칙을 따른다.

### 2.3 시드 RNG — 재현 가능한 런

주머니 셔플, 문방구 상품, 팩, 보스, 확률 효과가 전부 하나의 시드 기반 난수 생성기를 통과한다. 엔진 내부에서 `Math.random()`은 금지다. 같은 시드는 같은 런을 만들기 때문에 버그 재현, 밸런스 비교, 커스텀 시드 공유가 모두 가능해졌다.

### 2.4 중앙 밸런스 테이블

핸드 크기, 글자 Chips, 패턴 보상, 문방구 확률, 보스 배율 등 조정 가능한 수치는 전부 `balance.ts`에 모았다. 로직 안의 매직 넘버를 없애고, 설계 문서의 표·테스트·시뮬레이션이 하나의 값을 기준으로 움직이게 했다.

### 2.5 계산과 연출의 일치

점수 설계는 즉시 보상과 장기 계획을 함께 보여주기 위해 두 층으로 나뉜다.

- **단어 점수 — 즉시 확정:** 글자 Chips → 단어 길이 → Register Mult → 재질·폰트·에디션 → Word Hand → 이모지 타일 순으로 계산해 제출 즉시 커밋한다. 사전에 없는 조합도 제출은 되지만 **Gibberish**가 되어 기본 글자 점수만 받고 문장 패턴에 빈칸을 남긴다. 막힌 핸드의 탈출구이자, 블라인드 문장 보너스를 포기하는 대가다.
- **문장 점수 — 계속 투영, 마지막에 확정:** 문장 보너스는 매 페이즈 누적하지 않고 현재 배열 기준으로 다시 계산해 **미리 보여주기만** 하다가 라운드 종료 시 한 번만 확정한다.

```text
최종 점수 = (커밋된 단어 점수 + 문장 Chips) × 문장 Mult
```

엔진은 최종 숫자만 반환하지 않고 **어떤 타일과 Emoji Tile이 어떤 순서로 Chips/Mult를 바꿨는지** 점수 이벤트 로그로 반환한다. UI는 이 로그를 그대로 재생한다. 정산 완료 화면은 고정 지연 시간이 아니라 애니메이션의 **완료 신호**를 기다리므로, 효과 개수나 게임 속도로 정산 길이가 변해도 승리·패배 화면이 연출보다 먼저 뜨지 않는다. 연출의 정확성을 시각 효과가 아니라 **게임 상태 정합성 문제**로 다룬 결정이다.

### 2.6 오프라인·멀티 플랫폼 전제

Windows 빌드는 Electron이 `dist/index.html`을 `file://`로 직접 연다. 외부 CDN, 런타임 사전 다운로드, 절대 경로 의존을 모두 제거하고 폰트·이미지·사전을 번들에 포함했다. 저장 데이터는 **진행 중인 런**과 **장기 프로필**을 분리하고 프로필 슬롯 3개를 지원해, 런 데이터 버전이 바뀌어도 수집 기록이 손상되지 않는다.

### 2.7 UI·아트 방향

출판 작업대라는 세계관 위에 픽셀 아트와 CRT 연출을 결합했다.

- **Sentence Tray:** 플레이한 단어가 왼쪽부터 쌓이며 격식·품사·현재 문장 패턴을 한눈에 보여주는 대표 UI
- **Pixel/CRT:** 각진 패널, 단단한 오프셋 그림자, 스캔라인과 블룸 — 설정에서 강도와 모션 감소 가능
- **Shared Tooltip:** 글자 타일, Emoji Tile, 카드, 바우처, 주머니 등 모든 오브젝트가 동일한 정보 체계를 사용
- **Bilingual UI:** 엔진 식별자는 그대로 두고 표시 문자열만 한국어·영어로 분리
- **Guided Intro:** 첫 핸드에 `YELLOW`를 배치해 색상 해금과 단어 제출을 실제 조작으로 동시에 학습

## 3. 프로젝트 개발 과정

### 3.1 단계별 진행

**1단계 — 콘셉트와 규칙 범위 정의**
포커의 핸드·수트·조커를 그대로 복제하지 않고 각각을 Word Hands, Register Suit, Sentence Pattern, Emoji Tile로 재해석했다. **자유 문장의 의미 판정은 범위에서 제외**하고 품사 배열만 판정한다는 원칙을 먼저 못 박았다. 이후 모든 규칙과 수치는 GDD를 단일 기준으로 관리했다.

**2단계 — 헤드리스 코어 루프**
68개 알파벳 타일 주머니, 셔플·드로우, 핸드, 버리기, 단어 제출, Gibberish 경로를 UI 없이 실행되는 TypeScript 엔진으로 구현했다. 이 단계부터 모든 무작위 선택을 시드 RNG로 통일했다.

**3단계 — 단어·문장 점수 확장**
글자 Chips, 단어 길이, 어휘 격식, Word Hands를 단어 점수에 결합하고 12종 Sentence Pattern 판정을 구현했다. 여기서 **두 층 정산 구조**(단어=즉시 확정, 문장=마지막 확정)를 도입했다.

**4단계 — 로그라이트 콘텐츠 시스템화**
이모지 타일을 데이터와 이벤트 훅으로 정의하고 문방구·팩·바우처·보스·Starting Pouch·Record를 같은 엔진 위에 확장했다. 수치가 흩어지지 않도록 튜닝 값을 `balance.ts`로 모았다.

**5단계 — 플레이 경험과 피드백**
React UI에 Sentence Tray, 정산 애니메이션, 공통 툴팁, 문방구, 컬렉션을 구현했다. 엔진 점수 로그를 순서대로 재생하고, 고정 타이머 대신 정산 완료 신호로 다음 화면을 열었다. `YELLOW`를 직접 만드는 가이드 튜토리얼과 Chromatic Unlock도 이 단계에서 결합했다.

**6단계 — 데스크톱과 저장 구조**
웹 빌드를 Electron에서 오프라인 실행하도록 외부 네트워크 의존을 제거했다. 진행 중 런과 장기 프로필 데이터를 분리하고 프로필 슬롯 3개를 지원하도록 저장 경계를 설계했다.

**7단계 — 시뮬레이션과 회귀 검증**
헤드리스 자동 플레이로 목표 점수 곡선과 콘텐츠 분포를 확인하고, 플레이테스트에서 나온 정산 타이밍·저장·UI 문제를 회귀 테스트로 고정했다.

### 3.2 해결한 핵심 문제

**문제 1 — 자연어의 무한한 경우의 수**
자유 문장을 의미까지 판정하면 결과가 불투명하고 오프라인 재현이 어렵다.
→ 단어별로 미리 구축한 품사 후보를 사용하고, 전체 배열을 유한한 패턴과 비교했다. 다중 품사 단어는 가능한 배치를 탐색하되 최고 패턴 하나만 채택했다.
→ **결과:** 설명 가능하고 결정론적이며 테스트 가능한 문장 시스템.

**문제 2 — 즉시 점수와 문장 보너스의 충돌**
페이즈마다 문장 보너스를 누적하면 문장이 바뀔 때 중복 점수나 감소하는 점수가 생긴다.
→ 단어 점수는 즉시 커밋, 문장 보너스는 매번 덮어쓰는 투영값으로 분리해 종료 시 한 번만 확정했다.
→ **결과:** 라운드 점수는 절대 줄지 않으면서, 다음 단어가 만들 문장 가치는 실시간으로 보인다.

**문제 3 — 콘텐츠 증가로 인한 분기 폭발**
수백 개 효과를 메인 파이프라인에서 직접 처리하면 수정 영향 범위와 회귀 위험이 급격히 커진다.
→ 이벤트 버스, 데이터 레지스트리, 공통 소유 가능 여부 검사, 중앙 밸런스 테이블을 도입했다.
→ **결과:** 150개 Emoji Tile과 21종 보스, 32종 바우처를 동일한 방식으로 관리한다.

**문제 4 — 복잡한 계산을 플레이어가 이해하기 어려움**
최종 점수만 크게 보여주면 어떤 빌드가 효과적이었는지 학습할 수 없다.
→ 점수 기여도를 발생 순서대로 분리해 실제 오브젝트의 움직임·숫자·툴팁에 연결했다. 문장 패턴, 수식어, Unison, 후처리 효과의 출처도 각각 표시한다.
→ **결과:** 규칙이 많아져도 플레이어가 선택과 결과의 인과를 추적할 수 있다.

### 3.3 검증과 품질 관리

2026-08-20 기준 로컬 검증 결과:

```text
Test Files  123 passed (123)
Tests       1167 passed (1167)
Duration    10.23s
```

테스트는 점수 계산뿐 아니라 다음 경계까지 다룬다.

- 시드 RNG와 가방 구성
- 다중 품사 문장 패턴과 Gibberish 처리
- 보스·문방구·팩·바우처·경제 흐름
- Emoji Tile 로스터와 발동 순서
- 정산 완료 신호와 화면 전환 타이밍
- 튜토리얼 잠금, 툴팁, 모션 감소, 접근성
- 프로필별 저장 분리와 데스크톱 파일 저장
- 오프라인 빌드, 에셋 규격, 번역 키 무결성

배포 빌드는 데이터·에셋·번역·타입·엔진 의존성 순환·글리프 범위를 먼저 검사한 뒤 Vite 빌드를 수행한다. 데스크톱 빌드에는 외부 네트워크 의존성을 찾는 별도 오프라인 검사가 추가된다.

### 3.4 구현 결과

- 단어 하나의 퍼즐을 문장과 런 전체의 전략으로 확장했다.
- 자유 자연어 판정의 불확실성을 걷어내면서도 다중 품사와 수식어를 살린 문법 퍼즐을 만들었다.
- 150개 Emoji Tile을 하드코딩 없이 확장 가능한 이벤트 구조로 관리한다.
- 브라우저와 오프라인 Windows 앱이 같은 엔진과 데이터를 사용한다.
- 수치 조정 → 시뮬레이션 → 자동 테스트가 이어지는 반복 가능한 밸런스 환경을 만들었다.
- 색과 소리의 해금을 규칙에 결합해 제목·튜토리얼·수집 요소가 하나의 경험이 되게 했다.

## 4. 배운 점

**① 아이디어를 줄이는 것이 곧 설계다.**
가장 크게 배운 것은 복잡한 아이디어를 그대로 구현하는 것보다 **재미가 남는 최소한의 판정 규칙으로 바꾸는 일**이 더 중요하다는 점이다. "자유 문장 이해"를 "품사 배열 패턴 매칭"으로 축소하자 오프라인 실행, 재현 가능한 테스트, 설명 가능한 UI가 한꺼번에 따라왔다. 기능을 포기한 게 아니라, 검증 가능한 형태로 번역한 것이었다.

**② 연출은 장식이 아니라 규칙을 가르치는 인터페이스다.**
로그라이트에서 점수 애니메이션은 꾸밈이 아니라 학습 도구다. 엔진의 계산 순서와 화면의 연출 순서를 **하나의 이벤트 로그**로 묶자, 플레이어가 복잡한 빌드를 스스로 이해하고 다음 선택에 활용할 수 있게 됐다. 반대로 연출 타이밍을 고정 지연으로 짐작했을 때는 승리 화면이 정산보다 먼저 뜨는 버그가 반복됐다 — 타이밍은 추정이 아니라 **신호**로 다뤄야 했다.

**③ 오래 가는 코드의 핵심은 기능이 아니라 경계다.**
게임 규칙과 UI, 런 데이터와 프로필 데이터, 즉시 점수와 최종 문장 점수를 분리한 결정이 새 기능을 넣을 때마다 회귀 범위를 크게 줄여 줬다. 경계를 먼저 그은 덕분에 콘텐츠가 수십 개에서 150개로 늘어도 파이프라인은 그대로였다.

**④ 문서와 코드는 같은 커밋에서 움직여야 한다.**
설계 문서를 단일 기준으로 삼았지만, 수치가 바뀔 때 문서를 함께 고치지 않으면 곧바로 "문서 따로, 코드 따로"가 된다. 실제로 이 저장소에서도 로스터 수치가 문서와 어긋난 적이 있었고, 이후 **값이 바뀌면 그 값을 언급한 모든 문서를 같은 작업에서 갱신**하는 규칙을 명문화했다.

**⑤ 확률은 통제하지 않으면 검증되지 않는다.**
모든 무작위를 시드 RNG 하나로 모은 것이 밸런싱 전체의 전제 조건이었다. 시드가 고정되니 버그를 재현할 수 있었고, 수천 회 자동 플레이 결과를 비교할 수 있었고, 밸런스 변경의 효과를 감이 아니라 수치로 말할 수 있었다.

## 5. 앞으로의 계획

- **모바일 빌드:** 현재 Android·iOS 앱은 미구현이며 Capacitor 같은 패키징 계층을 검토 중이다. 반응형 레이아웃, 터치 조작, 모바일 저장소 어댑터를 완성한 뒤 실기기 QA를 진행한다.
- **밸런스 고도화:** 자동 플레이 결과와 실제 플레이 로그를 함께 분석해 문장 패턴 선택률, 라운드 스킵 비율, 특정 빌드 편중을 조정한다.
- **조작과 접근성:** 터치 환경의 길게 누르기, 작은 화면의 정보 배치, 모션 감소와 입력 방식별 사용성을 개선한다.
- **데스크톱 배포 완성:** Windows 설치 파일, 코드 서명, Steamworks·Steam Cloud 연동을 준비해 실행 파일 단계에서 실제 배포 단계로 발전시킨다.
- **콘텐츠 품질 관리:** 새 콘텐츠를 늘리기보다 기존 150개 Emoji Tile과 보스·보상 간 중복 효과를 점검하고, 사전과 품사 데이터 품질을 지속 보정한다.

### 포트폴리오 페이지용 요약문

**Play the Wor!d**는 영어 단어를 만들고 품사 순서로 문장을 완성하는 덱빌딩 로그라이트입니다. 단어 내부의 반복·회문·모음 구조는 Word Hand가 되고, 단어의 격식은 수트가 되며, 여러 페이즈에 걸쳐 쌓인 품사는 12개의 Sentence Pattern으로 판정됩니다. 게임 규칙은 React와 분리된 헤드리스 TypeScript 엔진으로 구현했고, 모든 확률을 시드 RNG로 통제해 브라우저·Electron·자동 시뮬레이터에서 동일한 결과를 재현합니다. 150개의 Emoji Tile은 이벤트 훅 기반으로 확장되며, 현재 1,167개의 자동 테스트가 점수·진행·저장·UI 경계를 검증합니다.

### 추천 스크린샷 구성

1. **메인 플레이 화면** — Sentence Tray, 핸드, 점수, 이모지 타일 선반이 함께 보이는 장면
2. **단어 정산** — 글자 타일과 Emoji Tile 효과가 순서대로 발동하는 장면
3. **문장 완성** — `CAT EATS FISH` 같은 패턴과 최종 보너스가 표시된 장면
4. **Chromatic Unlock 전후** — 무채색 시작 화면과 `YELLOW` 플레이 후 색이 돌아온 화면 비교
5. **Stationery Shop** — 팩, 바우처, 상품, 마스코트가 보이는 장면
6. **Collection** — Emoji Tile, 단어, 패턴, 마스코트 등 장기 수집 요소
