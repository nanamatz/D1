# 역기획서 — Balatro: Endless Mode (무한 모드)

| 항목 | 내용 |
|---|---|
| 분석 대상 | Balatro (LocalThunk / Playstack, 2024) — Endless Mode |
| 장르 | 포커 기반 덱빌딩 로그라이크 |
| 분석 목적 | "클리어 이후 콘텐츠"의 저비용·고밀도 설계 패턴 도출 및 자사 프로젝트 적용 검토 |
| 분석 범위 | 진입 플로우 / 규칙 명세 / 수치 곡선 / 보상 구조 / 종료 조건 |
| 작성일 | 2026-07-31 |

---

## 1. 시스템 정의

**무한 모드**는 안테 8의 피니셔 블라인드(Finisher Blind)를 격파해 런이 "승리" 확정된 직후, 플레이어의 선택으로 안테 9부터 이어서 진행하는 포스트 클리어 모드다.

핵심 정의를 한 문장으로 압축하면 다음과 같다.

> **승리를 이미 확정한 상태에서, 자신의 빌드가 어디까지 버티는지 측정하는 무보상·무위험 테스트 베드.**

이 정의에서 세 가지 설계 축이 도출된다.

1. **무위험(No-risk)** — 승리 기록은 이미 확정되어 있어 이후 패배해도 회수되지 않는다.
2. **무보상(No-reward)** — 안테 8 이후 구간에 걸린 외적 보상이 사실상 없다.
3. **측정(Benchmark)** — 유일한 산출물은 "내가 도달한 안테 / 최고 점수"라는 숫자 하나다.

## 2. 진입 플로우

```
안테 8 피니셔 블라인드 격파
        │
        ▼
[승리 연출 / 런 승리 확정 · 기록 저장]
        │
        ├── "New Run"      → 런 종료, 신규 런 시작
        ├── "Main Menu"    → 런 종료, 메인 메뉴
        └── "Endless Mode" → 안테 9로 진행 (동일 런 상태 100% 승계)
```

**설계 포인트**

- 승리 판정과 런 종료가 **분리**되어 있다. 승리 저장이 선행되므로 이후 결과가 승리 기록을 훼손하지 않는다. 무한 모드 진입의 심리적 진입 장벽을 0으로 만드는 가장 중요한 구조적 장치.
- 덱, 조커, 소지금, 강화 상태, 핸드 레벨이 전부 승계된다. 별도 초기화·리셋이 없다.
- 다만 승리 화면에서 "New Run"이 기본 포커스에 가까운 위치에 배치되어, 패드 사용자가 관성적으로 확인 버튼을 눌러 무한 모드 진입 기회를 날리는 사례가 커뮤니티에서 반복 보고되었다. **포스트 클리어 분기 UI의 기본 선택지 배치는 실수 비용이 비대칭인 지점**이라는 교훈.

## 3. 규칙 명세

### 3-1. 승계되는 규칙 (안테 1~8과 동일)

| 요소 | 사양 |
|---|---|
| 안테 구성 | 스몰 → 빅 → 보스 블라인드 3단 구조 유지 |
| 요구 점수 배율 | 스몰 ×1.0 / 빅 ×1.5 / 보스 ×2.0 (기준 칩 대비) |
| 스킵 | 스몰·빅 스킵 후 태그 획득 가능, 보스 스킵 불가 |
| 상점 / 부스터 팩 / 바우처 | 전부 정상 작동 |
| 스테이크·덱 보정 | 그린/퍼플 스테이크 요구치 증가, 플라즈마 덱 요구치 ×2 등 그대로 적용 |

### 3-2. 무한 모드 고유 규칙

| 요소 | 사양 |
|---|---|
| 시작 안테 | 9 |
| 요구 점수 | 안테 9부터 별도 공식으로 산출 (3장 참조) |
| 피니셔 블라인드 | 안테 16, 24, 32에서 재등장. 타이밍 외 사양은 일반 보스 블라인드와 동일 |
| 컬렉션 표기 | 안테 16까지만 기준 점수를 열람 가능. 17 이상은 미표기 |
| 종료 조건 | 요구 점수 산출값이 `nan`이 되는 **안테 39**에서 강제 종료 (4-3 참조) |

**피니셔 블라인드의 8안테 주기 재사용**이 핵심이다. 신규 에셋 없이, 기존 "최종 보스" 연출을 주기적 마일스톤으로 재활용해 무한 반복 구간에 리듬을 부여한다. 무한 모드 전체 개발 비용 중 대부분은 상수 테이블 하나와 분기 하나에 집중되어 있다.

## 4. 수치 설계 분석

### 4-1. 요구 점수 공식

원본 로직(`functions/misc_functions.lua`의 `get_blind_amount`)은 다음 구조를 갖는다.

```lua
-- 안테 1~8: 수동 테이블 (공식 아님)
amounts = { 300, 800, 2800, 6000, 11000, 20000, 35000, 50000 }

-- 안테 9 이상: 공식 산출
k = 0.75
a = amounts[8]        -- 50000
b = 1.6
c = ante - 8          -- 무한 모드 진입 후 경과 안테
d = 1 + 0.2 * (ante - 8)

amount = floor( a * (b + (k*c)^d)^c )
amount = amount - amount % (10^floor(log10(amount) - 1))  -- 상위 2자리로 절삭
```

**설계 의도 해석**

- 안테 1~8이 공식이 아닌 **수동 테이블**이라는 점이 중요하다. 본편 8안테는 튜닝의 영역, 무한 모드는 생성의 영역으로 명확히 분리했다. 본편 난이도 곡선은 손으로 조율하고, 그 이후는 "어차피 죽는 구간"이므로 공식에 위임한 것.
- 상위 2자리 절삭은 가독성 장치다. `7,236,481` 대신 `7.200e6`으로 표기해 **숫자를 읽는 대상이 아니라 크기를 감각하는 대상으로 전환**시킨다.

### 4-2. 성장 곡선의 성질

지수부 `d = 1 + 0.2c`가 **c에 비례해 함께 증가**한다. 즉 밑과 지수가 동시에 커지는 이중 지수(super-exponential) 구조다.

```
log10(요구치) ≈ c · (1 + 0.2c) · log10(0.75c)   →   c에 대해 대략 2차 × 로그
```

반면 플레이어의 점수 성장 상한은 다음과 같다.

| 성장 수단 | 성질 |
|---|---|
| 핸드 레벨 / +칩 / +멀티 | 선형 |
| xMult 조커 중첩 | 지수 (조커 슬롯 5칸 상한) |
| 스케일링 조커 (라운드마다 증가) | 선형~지수 |
| Blueprint / Brainstorm 재귀 복사 | 지수 (슬롯 상한에 종속) |

**결론: 요구치는 이중 지수, 플레이어는 지수.** 조커 슬롯 5칸이라는 하드 상한이 존재하는 한 플레이어 곡선은 반드시 추월당한다. 즉 무한 모드는 **수학적으로 종료가 보장된 모드**이며, "무한"이라는 이름은 정직한 표기가 아니라 의도된 아이러니에 가깝다.

### 4-3. 종료 조건 — `naneinf`

- 안테 39의 요구 점수가 배정밀도 부동소수점 상한(약 1.8e308)을 초과한다.
- 상위 2자리 절삭 연산이 오버플로된 값에 적용되면서 **요구치 자체가 `nan`으로 확정**된다. 표시상의 문제가 아니라 실제 비교 대상 값이 오염된다.
- `nan`은 어떤 값과도 비교가 성립하지 않으므로, 플레이어가 `naneinf`(= 무한대 점수)를 뽑아도 클리어 판정이 나지 않는다. Mr. Bones(요구치의 25% 이상이면 사망 방지)도 `nan × 0.25 = nan`이라 작동하지 않는다.
- 결과적으로 **안테 39가 도달 가능한 최고 안테**이며, 커뮤니티는 "안테 39에서 naneinf 달성"을 무한 모드 클리어로 인정한다.
- 개발자는 이 종료가 사고였음을 인정하면서도 "상징적"이라며 수정하지 않겠다고 밝혔다.

> **분석 코멘트:** 의도치 않은 구현 한계가 콘텐츠의 최종 목표로 승격된 사례다. 테트리스의 킬 스크린과 동일한 구조로, 커뮤니티가 "게임의 진짜 엔딩"이라는 서사를 스스로 부여했다. 단, 이는 **결과적 성공**이지 재현 가능한 설계 방법론이 아니다. 모방한다면 종료 지점을 의도적으로 설계하고 연출을 붙여야 한다.

**구간 해석**

| 구간 | 성격 | 체감 |
|---|---|---|
| 안테 9~10 | 완충 구간 | 배율 2~5배. "아직 갈 만하다"는 착각 유도 |

안테 11~12의 급격한 계단(×41.7)이 사실상의 설계된 종착지다. Steam 토론에서 "안테 12는 별개의 게임 같다"는 반응이 반복되는데, 이는 밸런스 실패가 아니라 **의도된 컷오프**로 읽는 것이 타당하다. 대부분의 런을 두세 안테 안에 정리해 세션을 자연 종료시키는 역할을 한다.

## 5. 보상 구조 분석

| 보상 유형 | 무한 모드에서의 제공 여부 |
|---|---|
| 업적 | 안테 4·8에는 존재하나 그 이상 구간에는 사실상 없음 (안테 12가 일부 컬렉션 해금 조건으로 언급되는 정도) |
| 재화 / 메타 프로그레션 | 없음 |
| 신규 콘텐츠 | 없음 (피니셔 블라인드 재사용 외) |
| 컬렉션 진행 | **간접적으로 존재** — 위험 없이 상점을 계속 열 수 있어 미발견 조커/바우처 발견에 유리 |
| 기록 | 최고 안테 / 최고 점수 |

**핵심 통찰: 외적 보상을 거의 전부 제거한 것이 오히려 설계의 강점이다.**

- 보상이 있으면 무한 모드는 **의무**가 된다. 반복 파밍 압박이 생기고, 요구치가 이중 지수로 발산하는 구조와 정면 충돌한다.
- 보상이 없으므로 무한 모드는 **선택**으로 남는다. 진입 동기는 전적으로 "내 빌드가 얼마나 강한지 보고 싶다"는 내적 동기다.
- 부수 효과로, 승리 확정 후의 상점 접근권이 **컬렉션 수집 채널**로 기능한다. 소지금을 전부 리롤에 태워도 잃을 것이 없기 때문에, 많은 플레이어가 "미발견 카드 확인용"으로 매 런 무한 모드에 진입한다. 설계자가 명시적으로 배치한 보상은 아니지만 실질 리텐션에 기여하는 경로다.

### 플레이어 동기 구조

```
승리 확정 (성취 충족)
      │
      ▼
"그런데 이 빌드, 얼마나 센 거지?"  ← 승리로 해소되지 않는 잔여 호기심
      │
      ▼
무한 모드 진입 (손실 위험 0)
      │
      ▼
숫자가 과학적 표기법으로 전환되는 순간의 스펙터클
      │
      ▼
1차 벽에서 패배 → 좌절 없음 (이미 승리했으므로)
      │
      ▼
"다음엔 더 센 빌드로" → 신규 런
```

패배가 좌절이 아니라 **다음 런의 목표 설정**으로 전환되는 것이 이 루프의 요체다. 무한 모드는 리텐션 장치인 동시에 **세션 종료 장치**이기도 하다. 요구치가 폭발적으로 증가하므로 플레이어는 반드시 몇 분 안에 패배하고, 이 패배가 자연스러운 이탈 지점을 제공한다.

## 6. 설계 의도 종합

## 8. 자사 프로젝트 적용 검토

*(Play the Wor!d — 단어 조합형 로그라이트 웹게임 기준)*

### 8-1. 도입 시 즉시 적용 가능한 원칙

1. **승리 판정과 런 종료를 분리한다.** 클리어 기록을 먼저 저장한 뒤 무한 모드 분기를 노출한다. 이 하나만으로 진입 장벽이 사라진다.
2. **보상을 걸지 않는다.** 무한 모드 전용 재화나 해금을 붙이는 순간 의무 콘텐츠가 되고, 발산하는 요구치와 충돌한다. 산출물은 "도달 스테이지 / 최고 점수" 기록 하나로 제한한다.
3. **기존 최종 보스 연출을 N주기마다 재사용한다.** 신규 에셋 없이 무한 구간에 리듬을 부여하는 가장 저렴한 수단.
4. **요구치 표기를 축약 표기로 전환하는 임계점을 설계한다.** 숫자가 표기 방식을 바꾸는 순간 자체가 연출이다. 단어 게임 문맥이라면 "초판 → 중쇄 → 베스트셀러 → 판매부수 e표기" 같은 도메인 언어로 감싸면 몰입을 해치지 않고 크기 감각만 전달할 수 있다.

### 8-2. 웹 환경 고유 검토 사항

- **JavaScript의 `Number`는 배정밀도 부동소수점이다.** 발라트로와 정확히 동일한 1.8e308 상한을 공유한다. 즉 별도 처리 없이 무한 모드를 구현하면 동일한 `NaN` 종료가 재현된다.
- 선택지는 셋이다.
  1. **한계를 그대로 수용하고 의도적으로 연출한다** — 상한 직전 스테이지에 "출판 가능한 부수를 초과했습니다" 류의 종료 연출을 배치. 비용 최저, 서사적 완결성 확보.
  2. **`BigInt` 또는 가수·지수 분리 표현으로 전환한다** — 진짜 무한을 지향. 다만 점수 연산 전 구간의 리팩터링이 필요하고, 실익은 낮다.
  3. **요구치 곡선을 완만하게 잡아 상한 도달 전에 게임플레이가 먼저 붕괴하게 한다** — 가장 통제하기 쉬움.
- **권장: 1번.** 상한을 버그가 아니라 콘텐츠의 종착지로 명시 설계하고, 도달 시 전용 연출과 기록을 남긴다.

### 8-3. 곡선 파라미터 설계 가이드

발라트로 공식을 그대로 이식하기보다, 다음 세 지점을 먼저 정하고 역산할 것을 권장한다.

| 결정 항목 | 발라트로 대응값 | 권장 접근 |
|---|---|---|
| 완충 구간 길이 | 2안테 (9~10) | 클리어 직후 성취감 유지용. 1~3 스테이지 |
| 1차 벽 위치 | 안테 11~12 | **평균 플레이어의 실제 종료 지점.** 여기서 대다수가 끝나도록 배치 |
| 최종 종료 지점 | 안테 39 | 자료형 상한 또는 명시적 하드 캡. 전용 연출 필수 |

그 사이 구간은 이중 지수 형태(`base * (b + (k·c)^(1+m·c))^c`)로 채우되, `k`와 `m`을 조절해 1차 벽 위치를 맞춘다. 발라트로 기준 `k=0.75`, `m=0.2`.

## 9. 결론

발라트로의 무한 모드는 **신규 콘텐츠를 거의 만들지 않고 게임의 수명을 연장한 설계**의 모범 사례다. 실제 구현물은 상수 테이블 하나, 공식 하나, 분기 하나, 그리고 기존 보스의 주기적 재사용이 전부다.

그럼에도 이것이 유효하게 작동하는 이유는 세 가지 구조적 선택 덕분이다.

1. **승리를 먼저 확정시켜 위험을 0으로 만들었다** — 진입 장벽 제거.
2. **보상을 걸지 않아 의무가 아닌 선택으로 남겼다** — 발산하는 난이도와의 충돌 회피.
3. **곡선이 플레이어 성장률을 반드시 추월하도록 설계했다** — 세션 자연 종료 보장.

여기에 부동소수점 상한이라는 우연이 겹치며 `naneinf`라는 최종 목표가 생겼다. 이 부분은 **모방 대상이 아니라 교훈 대상**이다. 같은 효과를 원한다면 우연에 맡길 것이 아니라, 종료 지점을 의도적으로 설계하고 그에 걸맞은 연출을 준비해야 한다.
